插件是给 Trindle 增加功能的小附件，例如圆环中的图标、“设置”中的一个页面、通知，或者登录时就开始运行的东西。插件只来自 Trindle 自己的列表，这份列表带有签名，没有人能偷偷塞进别的插件。每个插件在加入之前都经过测试，并且各自在隔离环境中运行，在你于“权限”中允许之前，什么都不被允许。

你可以在“应用”的“插件”页面找到插件。[应用](apps.html#plugins) 说明了如何添加和移除它们。本页讲的是你可能在那里看到的红色文字。

![“应用”的“插件”页面。一张名为“内置”的卡片里有 Pocketkey 和一个关闭的开关，下面一张卡片说明插件从哪里来。](img/apps-plugins.png "你会看到：“应用”的“插件”页面。")

## 出问题时

当插件无法获取、安装或启动时，“应用”会在该插件的卡片下方，或在“插件的来源”下方，用红色文字说明，旁边有一个圆形的小按钮 **更多**。点按它，“帮助”就会打开对应该消息的页面。

- [插件被检查拒绝了](plugins.html#a-plugin-was-refused-by-the-check)：插件自己的说明文件没有通过。
- [插件的后台部分没有运行](plugins.html#a-plugin-s-background-part-is-not-running)：它已装好，但一直运行的那一部分没有启动。
- [插件无法下载或安装](plugins.html#a-plugin-would-not-download-or-go-in)：获取、解压或安装失败。
- [无法使用插件列表](plugins.html#the-plugin-list-could-not-be-used)：带签名的列表被拒绝，或它的记录已损坏。

“应用”的页面 [插件无法使用](apps.html#a-plugin-is-not-working) 讲了其余的情况：无法移除的插件、无法保存的权限，以及 Pocketkey 没有响应。

## 插件被检查拒绝了
Questions: 为什么提示插件没有通过 Trindle 的插件检查；为什么什么都没有安装；插件里的 Interface 是什么意思；为什么提示插件需要 Name；为什么提示某个程序不是插件自带的；为什么提示某个链接指向插件文件夹之外

每个插件都带有一个叫 `plugin.ini` 的小文件来描述它：名称、它增加了什么、它请求被允许做什么。Trindle 会检查这个文件两次。Trindle 的人在制作列表时检查一次，你的电脑在插件安装时再检查一次。只要有任何地方不符，插件就不会被安装。不会装到一半就停下。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它没有通过 Trindle 的插件检查，所以什么都没有安装，并且它需要一个 Name。旁边有一个圆形帮助按钮。](img/plugins-check-refused.png "你会看到：一个被检查拒绝的插件。")

红色文字显示的是第一个出错的地方。后面可能还有别的。你自己没法修改插件：要由插件的作者来修正。你可以这样做：

1. 过一段时间再点按这个插件的按钮。每次打开“插件”页面都会重新读取列表，修正后的插件会随下一份列表一起到来。
2. 看看“应用”的“更新”页面。更新的 Trindle 也许认识这个版本不认识的接口。
3. 告诉插件的作者，或使用“报告问题”，并引用红色文字。

检查会看哪些内容，以及它用的措辞：

- **文件。** “文件夹顶层没有可读取的 plugin.ini”和“plugin.ini 没有 [Plugin] 部分”。文件不存在、无法读取，或者缺少第一部分。
- **接口。** “[Plugin] 需要 Interface=1。”或“Interface=2 这个 Trindle 不认识：它认识 Interface=1。”插件是为另一个版本的插件运行方式写的。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它没有通过插件检查，并且需要一个 Interface 编号，旁边有圆形帮助按钮。](img/plugins-check-interface.png "你会看到：一个没有 Interface 行的插件。")

- **名称、版本和摘要。** “[Plugin] 需要一个由字母、数字、点和短横线组成的 Id，例如 org.example.Weather”，“需要 Name”，“需要 Version”，“Summary 只能是一行”。Name、Version 和 Summary 各是一行普通文字，最多分别为 48、32 和 200 个字符。
- **权限。** “权限 …… 不存在，现有的权限有：……”，后面是列表。插件只能请求 Trindle 有的权限。它不能同时请求网络和家庭网络。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它请求的某个权限并不存在，并列出了现有的权限。旁边有一个圆形帮助按钮。](img/plugins-check-permission.png "你会看到：一个请求了不存在的权限的插件。")

- **圆环图标。** “[Ring] 需要 Icon：插件文件夹里的一个 SVG 或 PNG 文件”，“Icon 指向 ……，但它不在插件的文件夹里”，“需要 Label”和“需要 Run，即点击后启动的内容”。
- **圆环图标上的菜单。** 最多八项，每项有一个最多 32 个字符的普通标签，一个由字母、数字、短横线和下划线组成的 id，只列出一次，并有自己的部分和自己的 Run。
- **它的设置页面。** “[Settings] 需要 Fields”，字段名称含有不允许的符号，字段没有自己的部分，缺少 Label，类型不是 switch、text、choice 或 note，开关的 Default 不是 true 或 false，选择项的 Choices 少于两个（最多 32 个，每个最多 48 个字符）或它的 Default 不是其中之一，以及说明文字没有 TextFrom 或有 Default。ChoicesFrom 或 TextFrom 的文件名由字母、数字、点、短横线和下划线组成，不能以点开头，不能含文件夹。
- **ShowWhen。** 字段可以设为只在另一个更靠前的字段取某个值时才显示。文字会说明违反了哪条规则：必须写成 `field=value`，必须指向另一个字段，必须指向更靠前的字段，必须指向自己没有 ShowWhen 的字段；对于开关，值是 true 或 false，对于选择项，值是它的 Choices 之一，而说明文字不保存任何设置，不能作为依赖。
- **挂接。** 当插件没有圆环图标、设置、后台部分、快捷键或通知权限时，会提示“[Background] 需要 background 权限”和“这个插件没有挂接任何内容”。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说这个插件没有挂接任何内容，以及它需要挂接什么。旁边有一个圆形帮助按钮。](img/plugins-check-hooks.png "你会看到：一个没有挂接任何内容的插件。")

- **程序。** “Run 必须指向插件文件夹内的程序”，“Run 指向 ……，但它不是插件自带的程序（不存在，或不可执行）”，以及“Run 无法作为命令读取”。
- **链接。** “…… 链接到了插件文件夹之外。”插件不能带有任何指向外部的链接。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说其中的一个文件链接到了插件文件夹之外，旁边有圆形帮助按钮。](img/plugins-check-links.png "你会看到：一个带有指向文件夹之外的链接的插件。")

- **快捷键。** 最多四个，每个有 id、有自己的部分、有不与 Trindle 的快捷键或该插件其他快捷键重复的 Keys，以及一个 Run。
- **要监听的端口。** “[Network] Listen”需要 network 和 listen 权限，而 listen 需要指定端口。最多四个，每个写成 `tcp:` 或 `udp:` 加上 1024 到 65535 的端口，不能重复，也不能是 Trindle 或常见服务用到的端口。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它没有通过插件检查，因为它在没有 network 权限的情况下监听网络，旁边有圆形帮助按钮。](img/plugins-check-listen.png "你会看到：一个没有 network 权限却在监听的插件。")

- **用 PIN 码解锁。** “只用于 Trindle 目录中的 Flow”和“需要 Run，即接收 PIN 码的命令”。

:::expert
这项检查是 `plugins::check`，它会收集发现的每一个问题。从目录安装时只显示第一个，出现在 `plugins-install-check` 中。它在压缩包的 SHA-256 与带签名列表中的相符之后，在任何东西被放入位置之前，对解压出的文件夹运行。id 与列表所指不同的插件，会在这之前就被拒绝（“压缩包里是 ……，而不是 ……”），如 [插件无法下载或安装](plugins.html#a-plugin-would-not-download-or-go-in) 所述。
:::

## 插件的后台部分没有运行
Questions: 为什么提示它的后台部分没有运行；插件的后台部分是什么；为什么提示没有桌面会话在运行；为什么提示它没有在 15 秒内启动；为什么提示找不到 trindle-plugin；为什么提示无法判断该加入哪个桌面会话

有些插件有一个一直在后台悄悄运行的部分，比如等待手机靠近的那种。它叫做后台部分。只有当插件请求了 **background** 权限并且你允许了它，插件才会有后台部分。它在你登录时启动，插件安装或更新时也会再次启动。

![“应用”的“插件”页面。一个虚构的插件 Weather 的卡片底部有红色文字，说它已安装，但它的后台部分没有运行，因为没有桌面会话在运行，旁边有圆形帮助按钮。](img/apps-plugin-not-running.png "你会看到：一个后台部分没有运行的插件。")

红色文字先说插件已装好，然后说明它的后台部分为什么没有运行。

- **“没有可加入的桌面会话，所以没有启动。请先登录。”** 这个部分要加入你的桌面。没有桌面会话，就没有可加入的东西。登录之后它就会启动。
- **“它没有在 15 秒内启动。”** 给了它 15 秒，它没有回应。请退出登录再重新登录：每次登录时这个部分都会重新启动。

![“应用”的“插件”页面。一个虚构的插件 Weather 的卡片底部有红色文字，说它的后台部分没有运行，因为它没有在 15 秒内启动，旁边有圆形帮助按钮。](img/plugins-not-running-slow.png "你会看到：一个启动太慢的后台部分。")

- **“找不到 trindle-plugin，无法启动它。”** 启动插件的程序不在 Trindle 查找的位置，所以这台电脑上的 Trindle 可能不完整。请看“应用”里的“更新”，如果仍是这样，请使用“报告问题”。
- **“无法判断该加入哪个桌面会话（……），所以没有启动。”** 你打开了不止一个桌面会话，这个部分分不清哪个是你的。请退出多余的会话。
- 更新说明末尾的 **“…… 它的后台部分没有运行：……”**。新版本没有装上，原来的版本也没有在运行。后面依次给出各自的原因。处理完原因后，请再试一次更新。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它的文件不是目录里列出的那个，并且它的后台部分没有运行，因为没有桌面会话在运行。旁边有一个圆形帮助按钮。](img/plugins-swap-not-running.png "你会看到：一个没有装入的更新，并且后台部分没有运行。")

如果你没有在“权限”中允许 **background**，插件就没有后台部分，也就没有什么要运行的。

:::expert
这个部分以 `trindle-plugin run ID background` 启动，如果有服务管理器，就放在你的服务管理器下它自己的组里（`systemd-run --user --scope`），所以结束启动它的会话不会让它结束。如果没有服务管理器，日志会这样说，这个部分会随会话一起结束。它只启动一次，每个人一个看守，并使用最后一个仍有响应的登录的 Wayland 屏幕。
:::

## 插件无法下载或安装
Questions: 为什么提示无法下载；为什么提示压缩包无法解压；为什么提示它的文件不是目录里列出的那个；为什么提示无法复制插件的文件；为什么提示它没有安装所以没有可更新的；为什么提示无法写入表明它来自 Trindle 目录的记录

安装一个插件分四步，四步都成功才会安装。

1. 只通过安全连接，从 Trindle 自己列表旁边获取它的文件。
2. 用 SHA-256（文件的指纹）检查这个文件正是带签名列表所指的那个。
3. 把它解压到一个临时位置，并在那里对它的 `plugin.ini` 运行检查。
4. 把它装好，如果是更新就覆盖旧版本，并留下一条记录，表明它来自 Trindle 的列表。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它无法下载，因为无法解析主机，旁边有圆形帮助按钮。](img/plugins-download-failed.png "你会看到：一个无法下载的插件。")

- **“无法下载：……”** 后面是下载程序给出的原因。通常是网络问题：没有连接、地址没有回应，或文件太大、耗时超过半小时。超过 500 MB 的文件会被拒绝。请检查网络连接，然后再点按一次按钮。
- **“无法启动 curl：……”** 下载用的程序不存在，或无法运行。
- **“它的文件不是目录里列出的那个（SHA-256 不同），所以没有安装。”** 收到的不是被签名的那个。它已被丢弃。这正是保护你免受被改动文件影响的办法。请稍后再试；如果一直这样，请用“报告问题”告诉 Trindle。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它的文件不是目录里列出的那个，所以什么都没有安装，旁边有圆形帮助按钮。](img/plugins-hash.png "你会看到：一个不是所列文件的插件文件。")

- **“无法解压归档：……”**、**“无法启动 tar：……”** 文件到了，但打不开。后面是解压程序说的第一行。
- **“归档的顶层，或顶层的那一个文件夹里，没有 plugin.ini。”** 文件打开了，但它的结构不像插件。
- **“归档里是 ……，而不是 ……，所以没有安装。”** 里面的插件 id 与列表所指的不同。它被拒绝。
- **“无法复制插件的文件。”** 最后一步失败了，通常是因为磁盘已满，或插件的文件夹无法写入。什么都没有装上。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说插件的文件无法复制，旁边有圆形帮助按钮。](img/plugins-copy-failed.png "你会看到：无法复制的文件。")

- **“已装好，但无法写入表明它来自 Trindle 目录的记录：……”** 插件已装好，但缺少这条记录。请移除它再重新添加。

![“应用”的“插件”页面。一个虚构的插件 Tides 的卡片上有红色文字，说它已装入，但无法写入“它来自 Trindle 目录”的记录，并写明了原因，旁边有圆形帮助按钮。](img/plugins-install-note.png "你会看到：一个装入了但没有记录的插件。")

- **“它没有安装，所以没有可更新的。”** 对一个不存在的插件要求更新。请先安装它。
- **“无法创建临时文件夹：……”** 没有地方可以解压。后面是原因，通常是磁盘已满。

:::expert
压缩包是 `.tar.zst`。下载使用 `curl`，带 `--proto =https` 和 `--proto-redir =https`，并有大小上限，压缩包的时间上限为 1800 秒。`tar` 以 `--no-same-owner --no-same-permissions` 运行，会去掉开头的 `/`，并拒绝含 `..` 的名称，所以不会有东西落在临时文件夹之外。无论结果如何，安装结束时临时文件夹都会被删除。这条“来自列表”的记录，是区分来自目录的 Flow 与其他任何插件的唯一依据，所以只有在 SHA-256 相符之后才会写入。
:::

## 无法使用插件列表
Questions: 为什么提示没有使用 Trindle 的插件目录；为什么提示目录不是用 Trindle 的密钥签名的；为什么提示插件更新已暂停；“重新开始”有什么作用；为什么提示当前显示的是上一份完好的目录；为什么提示目录的版本更新

每次打开“插件”页面，Trindle 都会从自己发布的地址读取插件列表。在信任这份列表之前，“应用”会用 Trindle 自带的密钥检查列表的签名。任何一项检查没有通过的列表都不会被使用，上面的插件也不会被提供。如果之前保存了一份完好的列表，就会显示那一份，红色文字会这样说明。

![“应用”的“插件”页面。“插件的来源”卡片上有红色文字，说插件目录没有用 Trindle 的密钥签名，所以没有使用，并且显示的是上一份好的目录。旁边有一个圆形帮助按钮。](img/plugins-list-refused.png "你会看到：一份被拒绝的插件列表。")

- **“这个 Trindle 没有用来校验插件目录的密钥，所以不接受任何目录。”** 这份 Trindle 里缺少密钥。请在“应用”的“更新”中更新 Trindle。
- **“Trindle 的插件目录没有签名，所以没有使用。”** 以及 **“签名的长度不是签名应有的长度”**、**“不是用 Trindle 的密钥签名的”**。列表被改动过，或者在你和读取地址之间有东西改动了它。请稍后再试，如果一直这样，请使用“报告问题”。
- **“…… 没有说明它的编号”** 和 **“…… 比之前接受的那个更旧（编号 ……，之前为 ……）”**。每份列表都带有一个递增的编号，这样旧的列表就不能被放回去。请稍后再试。

![“应用”的“插件”页面。“插件的来源”卡片上有红色文字，说这份目录比之前接受的那份旧，写出了两个编号，并且显示的是上一份好的目录。旁边有一个圆形帮助按钮。](img/plugins-list-older.png "你会看到：一份比之前接受的更旧的插件列表。")

- **“…… 已签名但无法读取，所以没有使用：……”**。后面是原因：它不是文本、超过 1 MB 因而太大不可能是列表、没有带 Format 的 `[Catalogue]` 部分，或者它的版本比这个 Trindle 能读取的更新。版本更新表示 Trindle 需要更新。无论哪种情况，插件列表都不会被使用。
- **“…… 被略过：……”**。列表上有一个插件被略过，因为它的某个条目有误，例如它的 id、名称和版本、压缩包名称、SHA256、一个不存在的权限，或它的图标。其他插件仍然会提供。
- **“插件更新已暂停：插件列表已损坏。”** Trindle 会记录它接受过的最高列表编号。如果这条记录损坏了，更新就会停止，而不是冒险接受旧列表。**重新开始** 会要求输入管理员密码，并重新开始记录。

![“应用”的“插件”页面。“插件的来源”卡片上有红色文字，说因为插件列表已损坏，插件更新已暂停，旁边有圆形帮助按钮。](img/plugins-list-paused.png "你会看到：插件更新已暂停。")

- 点按 **重新开始** 之后出现 **“未完成：……”** 或 **“无法清除该记录：……”**。密码框被关闭了，或者记录无法清除。请再试一次。

:::expert
签名是 Ed25519，用内置在 Trindle 中的公钥检查。接受过的最高编号的记录保存在这台电脑上，这样列表就不能被回滚。如果签名通过但文本不是目录（没有带 `Format=` 的 `[Catalogue]` 部分），或大于列表允许的最大值（1 MB），列表同样会被拒绝。列表中属于其他插件接口的条目会被悄悄略过，因为更新的列表可能含有这个 Trindle 运行不了的插件。
:::
