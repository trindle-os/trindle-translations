## 软件包无法配置
Questions: dpkg error processing package 是什么意思；为什么提示 errors were encountered while processing；subprocess installed post-installation script returned error 是什么意思；为什么更新卡在某一个软件包上；dpkg was interrupted 是什么意思；为什么软件包只装了一半

意思是：Debian 已经解开了软件包，但最后一步，也就是设置它的那一步，失败了。Debian 就停在那里，让软件包处于做了一半的状态，之后的每次更新都会停在同一个地方，直到问题解决。

![“帮助”里名为“软件包无法配置”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误：dpkg: error processing package example-driver，旁边有一个复制按钮。](img/errors-package-configure.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 更新被停电、合上盖子或重启打断了，所以设置这一步从未运行。
- 软件包自己的设置脚本失败了。错误文字中失败位置上方的几行，会写出它无法处理的文件或服务。
- 它需要的另一个软件包还没有设置好。
- 磁盘已满，所以设置脚本无法写入它需要的内容。

解决步骤：

1. 重启电脑，这样就没有东西还在使用这个软件包。
2. 打开“应用”，进入“更新”，再点按一次“更新”。Debian 会从停下的地方继续。
3. 如果它仍停在同一个软件包上，请在下面的错误文字中找它的名字。它出现在 "processing package" 后面。
4. 如果磁盘快满了，请先腾出一些磁盘空间，再点按“更新”。
5. 如果仍然失败，请复制错误文字，把它写进报告里。参见 [报告问题](report-a-problem.html)。

:::expert
在终端中以管理员身份手动执行同样的修复：

- `dpkg --configure -a` 会设置每一个做了一半的软件包。
- `apt --fix-broken install` 会补全缺少的东西。
- `dpkg --audit` 会列出仍未设置好的软件包。
:::

## 驱动程序无法为新内核编译
Questions: dkms bad return status for module build 是什么意思；为什么更新后驱动程序没有编译成功；为什么新内核安装失败；dkms autoinstall failed 是什么意思；为什么内核更新后我的 Wi-Fi 或显卡驱动停止工作；module build for kernel failed 是什么意思

意思是：有些驱动程序，例如某些 Wi-Fi 芯片、显卡和虚拟机的驱动，每次内核变化时都要在你的电脑上重新编译。负责做这件事的是 DKMS。这次为新内核编译失败了，所以那个内核没有这个驱动。Trindle 仍然会安装内核和更新的其余部分，并写出这个驱动的名字，以及哪些功能会关闭，例如虚拟摄像头，直到有更新的驱动为止。

![“帮助”里名为“驱动无法为新内核构建”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，一次返回错误状态的模块构建，旁边有一个复制按钮。](img/errors-driver-build.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 驱动比新内核旧，还不能在它上面编译。
- 新内核的头文件没有安装，所以编译时没有可依据的东西。
- 编译时磁盘满了。
- 编译工具被移除了。

解决步骤：

1. 如果更新刚刚完成，先不要重启。你当前的内核仍有它的驱动。
2. 在“应用”的“更新”中再点按一次“更新”。能编译的新驱动，往往比新内核晚一两天到来。
3. 下面的错误文字会在 "dkms:" 或 "module" 后面写出驱动的名字。请记下它。
4. 如果你重启后某个设备停止工作，请在启动菜单（高级选项）中选择较早的内核。在那个内核上一切都会恢复正常。
5. 如果你不需要这个设备，请在“应用”中移除这个驱动，然后再点按“更新”。
6. 复制错误文字，把它写进报告里。参见 [报告问题](report-a-problem.html)。

:::expert
- `dkms status` 会列出每个驱动，以及它为哪些内核编译过。
- 编译日志在 `/var/lib/dkms/<name>/<version>/build/make.log`。其中第一个错误才是真正的原因。
- `apt install linux-headers-$(uname -r)` 会装上正在运行的内核的头文件。
:::

## 没有剩余空间
Questions: no space left on device 是什么意思；为什么提示磁盘空间不足；为什么磁盘满了更新就装不上；怎样为更新腾出磁盘空间；ENOSPC 是什么意思

意思是：磁盘，或者磁盘上存放系统的那一部分，没有更新所需的空间了。更新停了下来，所以不会有故意写了一半的东西，但可能有软件包处于做了一半的状态。

![“帮助”里名为“没有剩余空间”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，一个设备上没有剩余空间的写入错误，旁边有一个复制按钮。](img/errors-no-space.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 磁盘确实快满了，里面有“下载”文件夹中的文件、旧备份或大视频。
- 以前更新留下的旧内核和软件包文件越积越多。
- 磁盘上存放系统的那部分很小，而主文件夹所在部分还有很多空间。
- 许多小文件用光了文件条目，这也会显示为已满。

解决步骤：

1. 打开“文件夹”，看看最大的文件夹。删除或移走不再需要的内容。清空回收站，因为被删除的文件在此之前仍然占用空间。
2. 在“应用”中打开“已安装”，移除你不再使用的程序。
3. 再点按一次“更新”。如果有软件包处于做了一半的状态，腾出空间之后的第一次更新会把它完成。
4. 如果满的是系统那一部分，而你自己的文件很少，请在报告中说明，并附上下面的错误文字。

:::expert
- `df -h` 显示每个磁盘及其已用程度，`df -i` 显示还剩多少文件条目。
- `apt clean` 会删除不再需要的已下载软件包文件。
- `apt autoremove --purge` 会移除没有任何东西需要的旧内核和库。
:::

## 软件包数据库被锁定
Questions: could not get lock var lib dpkg lock 是什么意思；为什么提示另一个进程正在使用它；为什么更新运行时我不能安装；unable to acquire the dpkg frontend lock 是什么意思；为什么 apt 提示锁被占用

意思是：同一时间只能有一样东西更改已安装的程序，所以 Debian 在更改时会持有一把锁。别的东西占着这把锁，所以这次更改被拒绝了。什么都没有被更改。

![“帮助”里名为“软件包数据库被锁定”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，说无法获得锁以及哪个程序持有它，旁边有一个复制按钮。](img/errors-locked.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 已经有一个更新在运行，由“应用”、自动更新程序或另一个窗口启动。
- 你刚刚重启，上一次更新仍在后台收尾。
- 某次更新被中断，留下了锁。这种情况很少见，因为持有者停止时锁就会消失。

解决步骤：

1. 等几分钟。后台的更新通常会自己完成。
2. 关闭其他正在安装或更新的窗口，然后再点按一次按钮。
3. 如果十分钟后仍被锁定，请重启电脑。重启会结束所有持有锁的东西。
4. 如果刚重启就被锁定，请复制下面的错误文字。它会写出持有这把锁的程序的编号。

:::expert
- `fuser -v /var/lib/dpkg/lock-frontend` 会写出持有这把锁的程序。
- 在那个程序还在运行时，千万不要手动删除锁文件。这可能让软件包数据库损坏。
:::

## 下载失败
Questions: failed to fetch 是什么意思；为什么提示 hash sum mismatch；更新里的 404 not found 是什么意思；为什么提示 some index files failed to download；temporary failure resolving 是什么意思；为什么更新失败并提示 could not resolve

意思是：Trindle 无法从保存更新所需文件的地方取得这个文件，或者取到的文件与预期的不是同一个。没有从它安装任何东西。

![“帮助”里名为“下载失败”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，一次返回 404 Not Found 的获取失败，旁边有一个复制按钮。](img/errors-download.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 网络连接断了、非常慢，或者唤醒后还没有开始工作。
- 无法查询名称，因为网络的名称服务没有回应。
- 镜像，也就是保存这些文件的服务器，正忙，或者正在更新它自己的列表。这会出现 "Hash Sum mismatch" 和 "File has unexpected size"。
- "404 Not Found" 表示自从你的列表生成以来，这个文件已被更新的文件替换了。
- 会改写网页的网络，例如酒店或办公室的网络，返回了一个网页而不是文件。

解决步骤：

1. 打开任意一个网站，检查网络连接。
2. 等几分钟，再点按一次“更新”。正在更新列表的镜像很快就会恢复正常。
3. 如果是 "404 Not Found"，请在“应用”中再点按一次“更新”。它会先获取新的列表，这样就能找到新的文件。
4. 如果网络要求先登录，请先登录，然后再试。
5. 如果同一个文件失败超过一天，请把下面的错误文字复制到报告里。参见 [报告问题](report-a-problem.html)。

:::expert
- `apt update` 会重新获取列表，并显示是哪个地址失败了。
- `apt clean` 会移除下载到一半的文件，否则它们会让 "size mismatch" 反复出现。
:::

## 更新被暂缓
Questions: 为什么提示 kept back；not all updates went in 是什么意思；为什么内核没有更新；为什么固件没有更新；为什么 apt 会暂缓某些软件包

意思是：Debian 装上了它能安全装上的部分，并让消息中点名的软件包保持原样。这些软件包各自需要一样目前还没有的东西，例如更新的辅助软件包，所以现在更改它们会弄坏别的东西。

![“帮助”里名为“更新被暂缓”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，即被暂缓的软件包列表，旁边有一个复制按钮。](img/errors-kept-back.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 软件包需要一个来自别处的更新的软件包，而目前还没有人要求获取它。
- 自上次更新以来 Debian 的列表有了变化，再更新一次就能解决。
- 是你自己把这个软件包暂缓了。

解决步骤：

1. 在“应用”中再点按一次“更新”。许多软件包在第二次就能装上。
2. 如果又点名了同样的软件包，请把下面的错误文字复制到报告里。参见 [报告问题](report-a-problem.html)。
3. 与此同时，你的电脑照常工作，较早的启动内核仍保留在启动菜单中。

:::expert
- `apt-get -s --with-new-pkgs upgrade` 会在不更改任何东西的情况下，显示哪些被暂缓。
- `apt-cache policy <name>` 会显示想要哪个版本，以及来自哪里。
:::

## 软件包有未满足的依赖
Questions: unmet dependencies 是什么意思；为什么提示 you have held broken packages；depends but it is not going to be installed 是什么意思；为什么因为缺少另一个软件包，一个软件包装不上；apt fix-broken install 是什么意思

意思是：一个程序需要另一个程序，要求某个版本，而那个程序缺失、太旧或者挡了路。Debian 宁可拒绝这次更改，也不让电脑里留下一个运行不了的程序。

![“帮助”里名为“软件包有未满足的依赖”的部分，是从一次失败中打开的。先是步骤，下面是系统原话的错误，写出了这个软件包和它需要的那一个，旁边有一个复制按钮。](img/errors-dependencies.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 来自 Debian 之外的软件包，例如下载的 .deb 文件，要求 Debian 没有的东西，或者版本不同。
- 更新被打断，留下一部分是新的、一部分是旧的。
- 你把某个更新暂缓了，而别的东西需要更新的那个。
- Debian 的列表已过期，所以它找的版本后来已被替换。

解决步骤：

1. 在“应用”中点按“更新”，重新获取列表，然后再试。
2. 如果程序是你自己下载的，请在“应用”的“已安装”中移除它，然后再试。
3. 看看你暂缓的那些更新，暂时让它们通过。
4. 下面的错误文字会点名无法满足的软件包，以及它需要什么。如果上面的步骤没有帮助，请把它复制到报告里。参见 [报告问题](report-a-problem.html)。

:::expert
- `apt --fix-broken install` 会请 Debian 尽可能修复。
- `apt-cache policy <name>` 会显示有哪些版本可用，以及为什么选了其中一个。
:::

## 没有专门页面的错误
Questions: 帮助里没有列出的错误我该怎么办；为什么它说了我看不懂的话；帮助没有对应页面的错误是什么意思；怎样报告错误；错误文字有什么用

意思是：这个错误还不是“帮助”能通过它的文字认出来的，所以没有为它写专门的页面。Trindle 或系统给出的原话会原样显示在下面，这样你可以搜索它，或者把它随报告一起发送。

![“帮助”里为没有专门页面的错误打开的部分，是从一次失败中打开的。先是步骤，下面是系统原话的真实错误文字，旁边有一个复制按钮。](img/errors-unlisted.png "你会看到：步骤，然后是放在带复制按钮的框里的系统原话错误。")

可能的原因：

- 这是偶发的，例如网络连接掉了一下，或者某个程序当时正忙。
- 真正的问题出在磁盘、网络连接或密码上，而这段文字只是提到了由此失败的东西。
- 一个还没有人遇到过的罕见故障。

解决步骤：

1. 阅读下面的错误文字。第一行提到文件、程序、磁盘或地址的，通常就是关键。
2. 再试一次。许多错误只是一时的问题。
3. 检查三个常见原因：网络连接、磁盘的可用空间，以及有没有别的东西正在更新。
4. 点按错误文字旁边的圆形“复制”按钮，把它写进报告里。参见 [报告问题](report-a-problem.html)。请说明发生时你正在做什么。
